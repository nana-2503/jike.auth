# 通讯加密说明

## 概述

当应用配置了 `AppSecret` 和加密模式后，所有 SDK 接口的请求和响应都会进行 AES-256-CBC 加密，`app_code` 始终明文传输。

## AES 加密参数

| 参数 | 值 |
|------|------|
| 算法 | AES-256-CBC |
| 密钥 | AppSecret（不足32字节末尾补0） |
| IV | 每次随机生成16字节，附加在密文前面 |
| 填充 | PKCS7 |
| 编码 | Base64(IV + 密文) |

### 加密流程

1. 随机生成 16 字节 IV
2. 使用 AES-256-CBC + PKCS7 填充加密明文
3. 将 IV 拼接在密文前面：`IV(16字节) + 密文`
4. 对拼接结果进行 Base64 编码

### 解密流程

1. Base64 解码
2. 前 16 字节为 IV，剩余为密文
3. 使用 AES-256-CBC + PKCS7 解密

## 自定义步骤组合

管理员可在后台启用全局 SDK 通讯加解密的步骤组合模式。启用后，请求和响应会按 `encrypt` / `decrypt` 数组顺序执行步骤。

### 支持步骤

| 功能 | 步骤名 |
|------|--------|
| Base64 编码 | `base64_encode` / `base64-encode` |
| Base64 解码 | `base64_decode` / `base64-decode` |
| Hex 编码 | `hex_encode` / `hex-encode` |
| Hex 解码 | `hex_decode` / `hex-decode` |
| 字符串反转 | `reverse` |
| XOR 异或 | `xor` / `xor_key` / `xor-key` |
| RC4 加密 | `rc4_encrypt` / `rc4-encrypt` |
| RC4 解密 | `rc4_decrypt` / `rc4-decrypt` |
| SHA256 摘要 | `sha256` / `sha256_hex` / `sha256-hex` |
| AES-256-CBC 加密 | `aes_256_cbc_encrypt` / `aes-256-cbc-encrypt` |
| AES-256-CBC 解密 | `aes_256_cbc_decrypt` / `aes-256-cbc-decrypt` |
| ECC/ECIES 加密 | `ecc_encrypt` / `ecc-encrypt` / `ecies_encrypt` / `ecies-encrypt` |
| ECC/ECIES 解密 | `ecc_decrypt` / `ecc-decrypt` / `ecies_decrypt` / `ecies-decrypt` |

### key 取值

- `app_secret`
- `app_key`
- `app_code`
- `custom_fields.字段名`
- `custom.字段名`
- `custom:字段名`
- 自定义固定字符串

RC4 的 `key` 可使用普通字符串、Base64 或 Hex。

ECC 使用 P-256 ECIES 风格封装：加密步骤 `key` 填 P-256 公钥，解密步骤 `key` 填 P-256 私钥，支持 Base64/Hex 原始密钥。

### 多步骤示例

```json
{
  "encrypt": [
    { "op": "aes-256-cbc-encrypt", "key": "app_secret" },
    { "op": "base64-encode" },
    { "op": "reverse" },
    { "op": "hex-encode" }
  ],
  "decrypt": [
    { "op": "hex-decode" },
    { "op": "reverse" },
    { "op": "base64-decode" },
    { "op": "aes-256-cbc-decrypt", "key": "app_secret" }
  ]
}
```

## 签名算法

签名使用 SHA-256，基于应用配置的签名算法模板计算。

### 模板变量

- `[data]`：替换为加密后的 data 值（Base64 字符串）
- `[key]`：替换为 AppKey

### 模板示例

```
[data][key]
[key]_[data]_salt
```

### 计算步骤

1. 将模板中的 `[data]` 替换为加密后的 data 字符串
2. 将模板中的 `[key]` 替换为 AppKey
3. 对替换后的完整字符串计算 SHA-256 哈希

### 签名方向

| 场景 | 使用的算法模板 | 说明 |
|------|---------------|------|
| 客户端发送请求 | 服务端签名算法（ServerSignAlgo） | 客户端用此算法签名，服务端验证 |
| 服务端返回响应 | 客户端签名算法（SignAlgo） | 服务端用此算法签名，客户端验证 |

## 未登录接口请求格式

```json
{
  "app_code": "1234-56789012",
  "data": "AES加密后的Base64字符串",
  "sign": "SHA-256签名"
}
```

`data` 解密后包含公共参数和业务参数。

## 已登录接口请求格式

通过 Header 传递 Token：`X-Token: 登录返回的token`

```json
{
  "app_code": "1234-56789012",
  "data": "AES加密后的Base64字符串",
  "sign": "SHA-256签名"
}
```

## 响应格式

```json
{
  "data": "AES加密后的Base64字符串",
  "sign": "SHA-256签名"
}
```

`data` 解密后的 JSON：

```json
{
  "code": 0,
  "message": "成功",
  "data": { ... },
  "time": 1704067200,
  "uuid": "请求中的uuid",
  "client_id": "请求中的client_id"
}
```

## 公共参数

所有接口的 data 中可包含以下公共参数：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| feature | string | 是 | 设备特征码 |
| version | string | 是 | 客户端版本号 |
| client_id | string | 是 | 客户端ID（每次启动固定） |
| client_os | string | 否 | 客户端操作系统 |
| md5 | string | 否 | 应用版本MD5值 |
| uuid | string | 是 | 随机UUID（每次请求随机生成，用于匹配响应） |

## 客户端验证响应

1. 使用客户端签名算法验证 `sign`
2. 验证响应中的 `uuid` 和 `client_id` 与请求一致
